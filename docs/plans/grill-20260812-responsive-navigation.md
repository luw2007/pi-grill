## ① 背景与问题

上一轮交互优化已基本进入 `grill.ts`：理由与“其他”输入已内联，面板已展示进度，`Runtime.stateListener` 已能把外部 JSON 新增的 pending/current 题追加到当前面板，并以未读/移除标记提示变化，收敛关键词也已迁移为可配置项。

当前主要遗留问题是导航仍采用横向 tab/chip。题目数量增加、题目 id 或标题变长、终端变窄时，横向导航的信息容量与可浏览性不足；“提交”还被建模为额外 tab。此次首要问题明确为：用真正的题目列表与主内容布局替代横向 tab，而不是优先减少理由输入按键或全面重做所有交互。

## ② 目标与非目标

### 目标

- 宽度允许时采用响应式双栏：左侧常驻题目列表，右侧展示当前题及答题控件。
- 窄终端自动退化为上下布局，仍保留全局题目状态与当前题内容。
- 左侧列表展示题目 id、section、回答状态、未读及已移除提示，并支持题目较多时滚动。
- 保留现有动态新增题目、race rule、答案缓存、内联理由/“其他”输入与最终提交能力。
- UI 导航状态能够从唯一 JSON 状态源恢复。

### 非目标

- 不实现 literal HTML 或浏览器桥接；HTML 继续只是 JSON 驱动的外部镜像。
- 不在本轮优先改变普通选项确认后进入可选理由阶段的行为。
- 不改变十 section 访谈结构、题目状态机或已回答题不可变约束。
- 不把布局策略暴露为每次 `grill_ask` 调用参数。
- 不为旧版 extension 提供回滚兼容；采用前滚修复策略。

## ④ 方案设计

### 4.1 响应式布局

将渲染拆成可独立测试的三个阶段：

1. 根据题目/选项内容的可见宽度计算列表与主内容的最低可读宽度；
2. 根据当前终端宽度选择双栏或上下布局；
3. 分别渲染题目列表、当前题内容，再进行横向拼接或纵向组合。

双栏模式下，左栏展示题目列表，右栏展示题面、选项、推荐信息、内联文本输入或提交汇总。上下模式下，题目列表在上、主内容在下。布局不得因在题目间切换而频繁抖动：一次面板生命周期内应基于当前可见题目集合计算稳定需求宽度，仅在终端宽度或题目集合变化后重算，并加入迟滞区间或稳定化规则。

### 4.2 导航模型

- `←/→` 在题目列表区与答题区之间切换焦点。
- `Tab/Shift-Tab` 是切换分区的等价按键，尤其用于上下布局中补偿左右键与视觉方向不一致的问题。
- `↑/↓` 始终在当前分区内部移动：列表区选择题目，答题区选择选项。
- 列表选择题目时同步主内容，但不把仅浏览题目误记为回答。
- 当前焦点分区必须有明显视觉边框/标题强调；底部帮助文本随焦点和输入阶段变化。
- “提交”从横向 tab 移出，改为列表中的明确末项或右侧独立操作区；其焦点、可提交状态及汇总行为应延续现有 `allAnswered()` 规则。

### 4.3 动态题目与编辑态

保留现有热更新语义：新 pending/current 题加入列表并标未读，不抢占当前焦点。外部移除正在编辑的题时，保留该题的本地 composing 状态，允许提交后由既有 race rule 转为 `deprecated`。列表选中项被移除且没有编辑内容时，选择相邻有效题；没有有效题时进入提交/空态。

### 4.4 UI 状态检查点

用户决定将 UI 状态全部持久化到唯一 JSON，但不逐键写盘。实现“可恢复检查点”：

- 选择题目、切换分区、进入提交区、提交答案时立即原子写入；
- 列表滚动偏移与选项位置采用防抖写入；
- 关闭面板前刷新尚未落盘的检查点；
- watcher 收到由本组件自身写入产生的事件时，通过内容比较或修订号去重，避免反馈环；
- 恢复时先校验题目 id 与索引边界，对已移除/不存在的选中项执行确定性修复。

## ⑤ 备选方案与权衡

- **固定双栏**：导航结构稳定，但窄终端会挤压题面和选项，否决。
- **全部题目单栏展开**：浏览直接，但题多时滚动与重绘成本较高，且难保持当前题专注，否决。
- **命令面板式题目选择器**：主界面简洁，但丢失常驻全局上下文，否决。
- **Tab 作为唯一分区键**：在宽窄布局间语义稳定，是推荐方案；用户选择左右键为主，因此保留 Tab/Shift-Tab 作为等价替代路径。
- **UI 状态仅保存在组件内**：不改 schema、风险最低，是推荐方案；用户选择全部持久化，以换取恢复精确性，接受 schema 与 watcher 复杂度。
- **固定 100/120 列阈值**：确定、易测，但不能适应中英文题目和选项长度；用户选择内容驱动动态阈值，代价是必须防止题目切换导致布局跳变。

## ⑥ 接口/数据结构变更

将 `SCHEMA_VERSION` 从 1 升级到 2，并在 `GrillState` 增加必需的 UI 状态对象（字段名可在实现中微调，但语义须固定）：

```ts
type GrillUiState = {
  focusedPane: "questions" | "answer";
  selectedQuestionId: string | null;
  selectedOptionByQuestion: Record<string, number>;
  listScrollOffset: number;
  activeSurface: "question" | "submit";
  revision: number;
};

type GrillState = {
  schemaVersion: 2;
  // 既有字段不变
  ui: GrillUiState;
};
```

约束：

- `selectedQuestionId` 必须引用 pending/current/removed 且仍在 ledger 中的题，或为 `null`；恢复时若引用不可用题则确定性修复。
- 选项索引必须为非负整数，并在读取时钳制到当前选项范围；“其他”虚拟选项是否落盘须采用显式稳定表示，避免数组长度变化错位。
- `listScrollOffset` 必须为非负整数，并按当前列表长度钳制。
- `revision` 只用于抑制自身 watcher 回声和判断新旧 UI 检查点，不替代题目状态机。
- 新版启动时自动将合法 v1 状态迁移为 v2，初始化 UI 默认值并原子写回；迁移不得改写已有题面、选项、用户选择、理由或 pinned 内容。
- `grill_ask` 工具参数、`AskQuestion` 与 `AskAnswer` 对外契约保持不变。

## ⑦ 风险与影响面

- **高频写入反馈环**：JSON 写入触发 `fs.watch → syncFromDisk → stateListener`，可能重复渲染或覆盖内存编辑态。使用语义检查点、防抖、revision/内容去重控制。
- **布局抖动**：内容驱动阈值若按当前题独立计算，会在切题时来回切换。应以可见题目集合的稳定测量值、上限钳制和迟滞规则决定布局。
- **CJK/ANSI 宽度错误**：必须使用 `visibleWidth` 与已有包装工具测量，不可使用字符串长度直接计算栏宽。
- **动态移除竞态**：选中或编辑题被外部移除时必须保留 composing 数据，并沿用 removed→deprecated race rule。
- **schema 前滚不可逆**：旧版 extension 会拒绝 v2 JSON。用户明确接受只前滚修复；部署前必须备份扩展代码与会话 JSON，并先验证迁移副本。
- **状态污染**：UI 字段加入业务 JSON 后，外部编辑者也必须保留并校验这些字段；访谈 prompt 和校验错误信息需要同步更新。
- **影响范围**：`GrillState` 类型/Schema、初始化与恢复、校验、持久化、watcher 同步、`askQuestions` 输入状态机与渲染、HTML/摘要读取新版 schema 的兼容。
